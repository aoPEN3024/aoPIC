# aoPIC

工事写真の撮影、黒板焼き付け、分類、台帳用データ出力を端末内で行う静的Webアプリです。クラウド共有を使用しない場合、従来どおり端末内だけで撮影とZIP出力を利用できます。

## 社内クラウド共有試験

現段階は青山塗装社内だけの試験運用です。Cloudflare Turnstileは正式な外部提供前に追加します。Anonymous Sign-Inは利用者が「現場共有を開始」を押した場合だけ実行され、公開ページを開いただけでは新しい匿名ユーザーを作りません。

現場データはSupabaseのRLSと非公開Storageで分離します。会社PASSまたは対象工事の工事PASSがなければ共有工事へ参加できません。公開設定にはProject URLと`sb_publishable_`で始まる公開キーだけを含み、会社PASS、工事PASS、工事ID、管理者UUID、秘密鍵は含みません。

匿名ユーザー数はSupabase Dashboardで定期確認します。所属のない古い匿名ユーザーは、aoALBリポジトリの運用資料にあるSELECTによる候補確認後だけ整理し、自動削除しません。

## 緊急停止

1. Supabase Dashboardで対象プロジェクトを開きます。
2. `Authentication`のAnonymous Sign-Insを無効化し、新規端末の匿名認証を停止します。
3. 必要ならGitHubでクラウド公開設定のマージコミットをrevertします。
4. 既存の端末内写真は削除されません。aoPICはローカル撮影とZIP出力を継続できます。

会社PASSが漏れた場合は、Supabase SQL Editorで新しい会社PASSへ変更して旧PASSを直ちに無効化します。既存現場や写真は削除しません。

## 管理者PASS（migration適用後）

工事を作成するときに、その工事専用の「管理者PASS」を設定します。別のPC・ブラウザ・ホーム画面版では、工事IDと管理者PASSを使って管理者として接続できます。

- 会社共通の会社PASS、一般社員用の工事PASS、工事ごとの管理者PASSは別のものです。
- 通常の工事PASSではメンバー権限だけが付与され、管理者にはなりません。
- 既存工事は、現在の管理者端末で初回設定するまで管理コード接続を利用できません。
- 停止中の端末でも正しい管理コードで管理者として復旧できます。恒久的に拒否する場合は管理コードも変更してください。
- 最後の有効な管理者端末は停止できません。
- 工事を切り替えても端末内写真、送信キュー、ZIP出力データは削除されません。写真の送信先はキュー登録時の工事のままです。

この画面機能はaoALB側の `202607290001_site_admin_recovery.sql` 適用後に使用できます。未適用環境では従来のローカル撮影・ZIP出力を維持します。
